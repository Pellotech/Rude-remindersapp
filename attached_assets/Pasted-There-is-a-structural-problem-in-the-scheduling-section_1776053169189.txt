There is a structural problem in the scheduling section of the app.
The date/time picking logic is split across TWO files:
- client/src/components/CalendarSchedule.tsx
- client/src/components/ReminderForm.tsx (inline multi-day section)

This causes bugs where changes in one place don't register in the other.
The fix is to consolidate EVERYTHING into one new component and delete the old ones.

━━━━━━━━━━━━━━━━━━━━━━━━━━

This single component handles EVERYTHING:
- Single day selection
- Multiple day selection (same UI, just tap more pages)
- Hour selection
- Minute selection

Props:
interface BookDatePickerProps {
  onScheduleChange: (result: {
    scheduledFor?: string;       // ISO string — set when 1 date selected
    isMultiDay: boolean;         // true when 2+ dates selected
    selectedDays: string[];      // ["monday","tuesday"...] for multi-day
    hasValidSchedule: boolean;   // true when dates AND time are chosen
  }) => void;
  onDateEventFired?: (type: 'date_today' | 'date_tomorrow' | 'date_future') => void;
}

Internal state (all lives here, nowhere else):
- currentIdx: number (which book page is showing, 0 = cover)
- selectedDates: Date[] (which dates user has confirmed)
- selectedHour: number | null
- selectedMinute: number (0, 15, 30, 45)

onScheduleChange FIRING LOGIC:
━━━━━━━━━━━━━━━━━━━━━━━━━━

Fire this callback every time selectedDates, selectedHour, 
or selectedMinute changes:

if selectedDates.length === 0:
  { scheduledFor: undefined, isMultiDay: false, 
    selectedDays: [], hasValidSchedule: false }

if selectedDates.length === 1 and selectedHour !== null:
  const dt = new Date(selectedDates[0]);
  dt.setHours(selectedHour, selectedMinute, 0, 0);
  { scheduledFor: dt.toISOString(), isMultiDay: false,
    selectedDays: [], hasValidSchedule: true }

if selectedDates.length > 1 and selectedHour !== null:
  const dayNames = ["sunday","monday","tuesday",
    "wednesday","thursday","friday","saturday"];
  { scheduledFor: undefined, isMultiDay: true,
    selectedDays: selectedDates.map(d => dayNames[d.getDay()]),
    hasValidSchedule: true }

if dates selected but no hour yet:
  { hasValidSchedule: false, ... }
